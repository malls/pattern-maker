# PM-15: Brand favicon: PM-1 mark (charcoal badge, 3x3 pixel grid, orange center LED) + head wiring

Human-requested: "make a favicon that fits with the brand." The brand currently defines
no app mark (BRANDING.md §2 covers wordmark/badge only), so this task also *defines* it.

## The mark

The PM–1 badge idiom carrying the product's core motif: a charcoal rounded square
(the badge) holding a 3×3 grid of paper pixels (the editor) whose center pixel is
orange (the live LED). Tokens only: `--charcoal #1B1B1A`, `--paper #FBFAF8`,
`--orange #FF4E00`. Flat — no glow, no gradient (glow doesn't survive 16px).

Geometry at 16×16 (favicon.svg viewBox): rounded rect 16×16 r=3.5 charcoal; nine 3×3
cells at positions {2.5, 6.5, 10.5} on both axes (3·3 + 2·1 gaps = 11, centered with
2.5 margin); eight paper cells, center cell orange.

## Deliverables

1. `public/favicon.svg` — hand-written, the geometry above (Vite serves `public/` at root).
2. `public/favicon-32.png` — 32×32 raster of the same mark (2× scale: r=7, cells 6px,
   gaps 2px, margin 5px), transparent outside the rounded corners. Safari does not
   support SVG favicons, so the PNG is the working icon there.
3. `public/apple-touch-icon.png` — 180×180, full-bleed charcoal square (no transparency,
   no rounded corners — iOS applies its own mask): cells 34px, gaps 12px, margin 27px.
4. PNGs generated by a scratchpad node script (zero-dependency minimal PNG encoder using
   node:zlib; RGBA, correct CRCs) — the script is throwaway, never committed; the PNGs are.
5. `index.html` head: SVG icon link + PNG fallback (order: PNG sizes=32x32 first so Safari
   picks it, SVG type=image/svg+xml after for evergreen), apple-touch-icon link,
   `<meta name="theme-color" content="#E7E6E1">` (plastic), and a one-line
   `<meta name="description">` in brand voice.
6. BRANDING.md §2: define the app mark (one bullet — geometry, tokens, usage) so the
   favicon is brand law, not an orphan asset.

## Acceptance criteria

- favicon.svg is valid SVG, uses exactly the three token hexes, geometry as specified.
- Both PNGs are valid (signature + IHDR dims verified), pixel-perfect to the mark spec:
  32px version has transparent corners; 180px version is full-bleed opaque.
- index.html links all three with correct rel/type/sizes; theme-color present.
- BRANDING.md §2 documents the mark; hexes match the assets.
- `npm run build` copies all three into dist/ and stays clean.

Complexity: low. Out of scope: og/social meta, README, deploy config.
